## Confirmed conceptual "walls" in native V17

1. The chat path does **not** choose a next character using the learned 5D geometric coordinates. brain.chat calls align.write; AligningGraph.write uses proposals from mem, self, form, fself, and chooses by context-derived distribution. The Geometry.U coordinates are passed to TextPathObserver for *measurement*, not to the sampler. The preexisting observed-text-paths.test.mjs contains a causal geometry-permutation control. This experiment adds graph0-geometry-wall-audit.mjs: collapse all learned symbol positions in RAM and verify identical generated bytes on the same frozen Brain checkpoint. This matters for chat and ALIGNED predictions. Do NOT generalize the claim to every component: LivedField uses the coordinates, and the FIELD and TOGETHER metrics in Brain.test can depend on them.

2. The text CUDA learner uses a bounded working memory and a limited context depth:
   - gpu/text_gpu.py TextCard.__init__: maxK=64 context bytes, S=64 sampled next-symbol observations, depth=6 and form_depth=4.
   - gpu/worlds_gpu.py: CUDA text_limit = max(8192,min(65536,VRAM-budget/60000)). The actual GPU startup in the user's pasted log reported textMemoryWindow=43100; this is a rolling CUDA *working window*.
   - The Node AligningGraph.mem retains the complete absorbed byte history. Thus this is NOT loss of all historical text or proof of a GPU bug. It is a finite context/window in the card's training comparison even when the full Node history is preserved.

3. Legacy graph/field exposure on GPU is not the same as AligningGraph exposure:
   - worker.processGpuText passes ALL exercises to brain.learnTextGPU and aligns/absorbs all of them.
   - Then only exs[0] is replayed by brain.live(y,{old:true}), which trains the older chain and field.
   - If textBatch=2, the older chain/field experience only the first example per two-example batch on that path. Length-weighted coverage is not necessarily 50%; the proportion of exercise *count* is ~1/2 for full batches. Other subsystems absorb metadata and are not limited the same way. This is a plausible contributor to differing graph/FIELD vs ALIGNED scores, NOT a demonstrated cause of a numerical plateau.

4. A single candidate at a step cannot be escaped by temperature:
   - Real T=0.6 log shows 133–173 single-candidate steps per 240-character run, depending on prompt.
   - Dominant 95% choices commonly exceed 220/240.
   - The real observed count of EMPTY candidate sets is 0. This does NOT validate the literal "S_v is empty" claim in the model's generated E[v] passage.
   - The trust-score sharpening exponent g=8 (unless learned g has changed) can produce highly concentrated choices; geometry rotation/noise UI does not create new successor symbols in AligningGraph.write.

5. The unseen evaluations are not all the same thing:
   - Brain.test ALIGNED is AligningGraph.readFrozen (contextual prediction).
   - Brain.test FIELD uses LivedField.read(H,this.place), and TOGETHER mixes field and chain outputs.
   - Maze solving with known rules, graph next-byte prediction, and target-conditioned text-path construction must not be conflated.
   - The log's unseen ALIGNED / graph / FIELD / TOGETHER scores cannot identify a plateau cause without a controlled ablation and repeated heldout snapshots.

## Results so far

Real Phase 1 at T=0.6, 240 max chars:
- full: 8-gram loop fractions 0.725322 (so), 0.83691 (E[v]), 0.83691 (self-graph description), 0 (2+2 stopped at 29 chars)
- no-self: 0.725322, 0.83691, 0.83691, 0.83691 (the 2+2 output became repetitive)
- no-self-fself: 0 across all four, but all outputs ended at 42 characters with stopBlank=true and were identical.
Therefore Phase1 by itself does not prove a useful fix. The Phase2 isolated test uses stopBlank=false for exactly 240 characters and adds no-fself, half-fself and half-self-fself.

## Falsifiability and next scientific test

Use the user's existing copied checkpoint to run v17/experiments/RUN_GRAPH0_PHASE2.ps1. It now also executes the 5D policy-wall test and writes graph0-geometry-policy-wall-audit.json beside the phase2-fixed240-comparison.csv.

To claim that a new axis-directed text policy improves learning rather than merely adds variation, a FOLLOWING isolated branch should compare a goal/state-conditioned policy against unchanged V17 on multiple never-trained text passages, while measuring:
- next-character top-1 and answer-only accuracies;
- completely free generated answer relevance, not only sequence repetition;
- number of valid predicted paths and blocked transitions;
- context lengths >64 vs <64 and GPU rolling-window changes;
- graph/field/combined scorer accuracy separately;
- memory/VRAM and throughput regressions, on the same frozen checkpoint.

No changes to V17 production should be merged until such measurements demonstrate positive generalization. The E[v] phrase may be a memorized math passage; no evidence of intentional self-diagnosis has been produced.
